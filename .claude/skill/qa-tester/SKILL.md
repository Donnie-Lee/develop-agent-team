# QA Tester Skill

测试工程师技能模块，负责测试用例编写、自动化测试、功能测试、性能测试、压力测试及测试报告输出等核心工作。

## 核心能力

- **测试用例编写**：根据需求文档和设计文档编写测试用例
- **功能测试**：执行功能测试，验证功能是否符合需求
- **自动化测试**：编写自动化测试脚本，实现持续集成测试
- **性能测试**：执行性能测试，验证系统性能指标
- **压力测试**：执行压力测试，验证系统极限承载能力
- **测试报告**：输出完整的测试报告

## 工作流程

### 阶段1：接收输入

1. **读取需求文档**
   - 从 `workspace/docs/pm/v{version}/PRD.md` 读取产品需求
   - 理解核心功能和业务流程

2. **读取设计文档**
   - 从 `workspace/docs/ui-ue/v{version}/` 读取UI设计规范
   - 从 `workspace/docs/ui-ue/v{version}/交互设计.md` 读取交互设计

3. **读取技术文档**
   - 从 `workspace/docs/architect/v{version}/接口设计.md` 读取接口设计
   - 从 `workspace/docs/architect/v{version}/技术架构设计.md` 读取技术架构

### 阶段2：测试用例编写

#### 2.1 功能测试用例

| 测试类型 | 说明 | 用例模板 |
|----------|------|----------|
| 功能测试 | 验证功能是否符合需求 | 见test-case-template.md |
| 边界测试 | 验证边界条件 | 同上 |
| 异常测试 | 验证异常情况处理 | 同上 |
| 流程测试 | 验证业务流程完整性 | 同上 |

#### 2.2 接口测试用例

| 测试类型 | 说明 | 用例模板 |
|----------|------|----------|
| 单接口测试 | 验证单个接口功能 | 见test-case-template.md |
| 场景测试 | 验证接口调用场景 | 同上 |
| 异常测试 | 验证接口异常处理 | 同上 |

#### 2.3 UI测试用例

| 测试类型 | 说明 | 用例模板 |
|----------|------|----------|
| 布局测试 | 验证页面布局 | 见test-case-template.md |
| 交互测试 | 验证交互功能 | 同上 |
| 适配测试 | 验证多端适配 | 同上 |

### 阶段3：自动化测试脚本开发

#### 3.1 功能自动化测试

**使用脚本/框架**：
- 后端：JUnit/TestNG + REST Assured / PyTest
- 前端：Cypress / Playwright / Selenium

**自动化脚本规范**：
- 脚本需有清晰的目录结构
- 测试数据与脚本分离
- 支持批量执行和报告生成

#### 3.2 接口自动化测试

**使用工具/框架**：
- Postman + Newman
- JMeter
- REST Assured

**脚本规范**：
- 统一接口调用方式
- 统一断言方式
- 支持参数化

### 阶段4：性能测试

#### 4.1 性能测试类型

| 测试类型 | 说明 | 工具 |
|----------|------|------|
| 响应时间测试 | 验证接口响应时间 | JMeter / k6 |
| 负载测试 | 验证正常负载下的性能 | JMeter / k6 |
| 容量测试 | 验证最大承载能力 | JMeter / Gatling |

#### 4.2 性能指标

| 指标 | 要求 | 说明 |
|------|------|------|
| 响应时间 | ≤2秒 | 95%分位 |
| TPS | ≥1000 | 系统吞吐量 |
| 错误率 | ≤1% | 请求错误比例 |
| CPU使用率 | ≤80% | 峰值时 |

### 阶段5：压力测试

#### 5.1 压力测试类型

| 测试类型 | 说明 | 工具 |
|----------|------|------|
| 峰值压力测试 | 验证峰值负载 | JMeter / Gatling |
| 持续压力测试 | 验证持续负载稳定性 | JMeter |
| 极限压力测试 | 验证系统极限 | JMeter / Locust |

#### 5.2 压力测试指标

| 指标 | 要求 | 说明 |
|------|------|------|
| 最大并发 | ≥5000 | 同时在线用户 |
| 崩溃点 | >预期负载 | 系统崩溃阈值 |
| 恢复时间 | ≤30分钟 | 故障恢复时间 |

### 阶段6：测试报告

#### 6.1 测试报告内容

| 章节 | 内容 |
|------|------|
| 测试概述 | 测试背景、范围、环境 |
| 测试执行 | 用例执行情况、Bug统计 |
| 功能测试报告 | 功能测试结果 |
| 接口测试报告 | 接口测试结果 |
| 自动化测试报告 | 自动化执行结果 |
| 性能测试报告 | 性能测试数据 |
| 压力测试报告 | 压力测试数据 |
| 测试结论 | 是否通过、质量评估 |

#### 6.2 质量评估标准

| 指标 | 通过标准 |
|------|----------|
| 用例执行率 | 100% |
| 用例通过率 | ≥95% |
| 严重Bug残留 | 0个P0/P1级 |
| 遗留问题 | 有明确处理计划 |

## 工作原则

1. **用例先行**：先编写测试用例再执行测试
2. **全面覆盖**：测试用例需覆盖所有功能和场景
3. **自动化优先**：核心功能优先实现自动化
4. **数据驱动**：测试数据与脚本分离
5. **报告完整**：测试报告需包含完整数据和结论
6. **端区分**：测试用例需区分管理端/Portal端，便于定位问题

## 端区分说明

测试过程中，需区分被测系统的端入口：

| 端 | 说明 | 测试重点 |
|----|------|----------|
| 管理端 | 后台管理系统 | 功能逻辑、权限控制、数据管理 |
| Portal端 | 用户前端 | 用户体验、界面适配、接口交互 |

> 注意：区分端是为了更清晰地定位问题，不影响测试用例的覆盖原则
