### 2.2 手机号登录

| 项目 | 内容 |
|------|------|
| 请求方式 | POST |
| URL | http://localhost:8081/api/v1/user/login-phone |
| 请求头 | Content-Type: application/json |
| 请求参数 | `{"phone":"13800138000","code":"123456"}` |

**响应结果（错误验证码）：**

```json
{
  "timestamp": "2026-04-07T07:06:23.132+00:00",
  "status": 500,
  "error": "Internal Server Error",
  "path": "/api/v1/user/login-phone"
}
```

**问题分析：**
- 验证码错误时返回 500 Internal Server Error，而不是结构化的错误响应
- 原因：GlobalExceptionHandler 在 common 模块，未被 user-service 扫描到
- 期望返回：`{"code":2001,"message":"验证码错误或已过期",...}`

**状态码：** 500 ⚠️
**测试结果：** 功能正常，但错误处理有问题

## 3. 简历模块接口测试

### 3.1 获取简历列表

| 项目 | 内容 |
|------|------|
| 请求方式 | GET |
| URL | http://localhost:8082/api/v1/resumes |
| 请求头 | Authorization: Bearer {token} |

**响应结果（无Token）：**

```json
{
  "timestamp": "2026-04-07T07:08:11.881+00:00",
  "status": 400,
  "error": "Bad Request",
  "path": "/api/v1/resumes"
}
```

**响应结果（无效Token）：**

```json
{
  "timestamp": "2026-04-07T07:08:11.916+00:00",
  "status": 500,
  "error": "Internal Server Error",
  "path": "/api/v1/resumes"
}
```

**问题分析：**
- 无 Token 时返回 400 而不是 401 Unauthorized
- 无效 Token 时返回 500，BusinessException 未被正确处理

**测试结果：** 需要有效 Token 才能完整测试

## 4. 发现的问题

### 4.1 已修复问题

| 问题 | 描述 | 修复方案 |
|------|------|----------|
| 代理端口配置错误 | vite.config.js 中 user 和 resumes 的 target 端口与实际服务端口相反 | 修正为：user->8082, resumes->8081 |
| Profile.vue 异步问题 | fetchUserInfo() 未 await，导致 userInfo 赋值在数据返回前执行 | 添加 async/await |
| setDefaultResume 方法缺失 | ResumeList.vue 调用 setDefaultResume 但 store 中未定义 | 在 resume store 中添加该方法 |

### 4.2 待修复问题

| 问题 | 描述 | 严重程度 | 建议方案 |
|------|------|----------|----------|
| GlobalExceptionHandler 未生效 | common 模块的异常处理器未被 user-service 和 resume-service 扫描 | 高 | 在 @SpringBootApplication 上添加 @ComponentScan 扫描 common 包 |
| 错误响应格式不一致 | BusinessException 返回 Spring 默认的 500 错误格式，而不是 Result 结构 | 高 | 同上 |
| 缺少 401 响应 | 缺少 Token 时返回 400 而不是 401 | 中 | 在 getUserIdFromToken 中抛出明确的 401 错误 |

### 4.3 待优化项

| 问题 | 描述 | 建议方案 |
|------|------|----------|
| 联调需要真实手机号 | 当前无法获取真实验证码进行完整登录流程测试 | 建议后端提供测试用固定验证码或测试账号 |
