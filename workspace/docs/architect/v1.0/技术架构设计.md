## 0. 技术选型理由分析

### 0.1 后端技术选型理由

| 技术 | 选型 | 理由分析 |
|------|------|----------|
| **Java 17** | ✅ 采用 | JVM生态最成熟，企业级稳定，适合复杂业务；团队人才储备多 |
| **Spring Boot 3** | ✅ 采用 | 标准化微服务框架，生态完善（Spring Cloud/Security/Data等）；自动配置简化开发 |
| **PostgreSQL** | ✅ 采用 | 支持JSON类型（简历半结构化数据）；全文检索；PostGIS地理信息扩展；MySQL相比更符合SQL标准 |

### 0.2 前端技术选型理由

| 技术 | 选型 | 理由分析 |
|------|------|----------|
| **React 18** | ✅ 采用 | 虚拟DOM性能好； Hooks模式简洁；社区最大、组件库最丰富；团队熟悉度高 |
| **Ant Design 5** | ✅ 采用 | 企业级UI规范；组件丰富；TypeScript支持好；阿里背书稳定 |
| **Tailwind CSS** | ✅ 采用 | 原子化CSS，开发效率高；自定义主题方便；配合Ant Design可覆盖大部分场景 |
| **Flutter** | ✅ 移动端采用 | 跨平台iOS/Android；自绘引擎性能接近原生；Google生态；Dart语言上手快 |
| **Taro** | ✅ 小程序采用 | React语法，与主站代码复用；支持微信/支付宝/抖音/百度多端；升级响应式快 |

### 0.3 AI服务选型理由

| 技术 | 选型 | 理由分析 |
|------|------|----------|
| **通义千问 Qwen** | ✅ 采用 | 阿里云，中文优化领先；与ASR/TTS同生态，集成成本低；API稳定性好 |
| **阿里云 ASR** | ✅ 采用 | 中文识别准确率98%+；实时流式识别；支持多地方言；按量计费 |
| **阿里云 TTS** | ✅ 采用 | 多音色选择（正式/亲和/活泼）；情感语音；流式输出延迟低 |
| **AI网关自建** | ✅ 采用 | 模型路由（通义/智谱切换）；限流熔断；Token计费统计；敏感词过滤 |

### 0.4 中间件选型理由

| 技术 | 选型 | 理由分析 |
|------|------|----------|
| **Redis Cluster** | ✅ 采用 | K-V缓存性能极高；支持集群模式高可用；支持多种数据结构；Spring Boot原生支持 |
| **RocketMQ** | ✅ 采用 | 阿里开源，国内社区活跃；事务消息支持好；延迟消息适合面试超时场景；比Kafka运维更简单 |
| **Elasticsearch** | ✅ 采用 | 题库全文检索；简历关键词搜索；聚合统计面试数据；Kibana可视化 |
| **OSS** | ✅ 采用 | 简历文件存储；海量存储；CDN加速；SDK完善 |

### 0.5 运维技术选型理由

| 技术 | 选型 | 理由分析 |
|------|------|----------|
| **Docker** | ✅ 采用 | 容器化事实标准；镜像仓库完善；环境一致性好 |
| **Kubernetes** | ✅ 采用 | 生产级编排；弹性伸缩；自愈能力；服务网格Istio兼容 |
| **Jenkins** | ✅ 采用 | 插件丰富；流水线即代码；团队熟悉；兼容GitLab CI |
| **Prometheus+Grafana** | ✅ 采用 | CNCF核心项目；指标采集强大；社区仪表盘丰富；AlertManager告警 |

## 7. 安全架构

### 7.1 安全措施

| 安全层级 | 措施 |
|----------|------|
| **网络安全** | VPC隔离、安全组、DDoS防护 |
| **传输安全** | HTTPS/TLS全链路加密 |
| **认证授权** | JWT + RefreshToken |
| **数据安全** | AES加密存储、敏感字段脱敏 |
| **接口安全** | 签名验证、参数校验 |
| **风控** | 登录异常检测、行为风控 |

### 7.2 JWT认证流程

```
1. 登录请求
   Client → Server: {phone, code} / {third_token}
   
2. 验证通过，生成Token
   Server: 生成 access_token (15min) + refresh_token (7days)
   
3. 返回Token
   Server → Client: {access_token, refresh_token}
   
4. 请求API
   Client → Server: Header: Authorization: Bearer {access_token}
   
5. Token验证
   Server验证Token，有效则执行业务逻辑
   
6. Token过期
   Client使用refresh_token换取新access_token
```

## 8. 性能设计

### 8.1 性能指标

| 指标 | 目标值 |
|------|--------|
| API响应时间(P99) | ≤500ms |

### 8.2 性能优化策略

| 优化点 | 策略 |
|--------|------|
| **接口缓存** | Redis缓存热点数据 |
