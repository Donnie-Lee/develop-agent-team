## 8. 技术实现

### 8.1 JWT认证

- AccessToken: 15分钟有效期 (900000ms)
- RefreshToken: 7天有效期 (604800000ms)
- Token黑名单: Redis存储

### 8.2 验证码

- 存储: Redis
- 有效期: 5分钟 (300秒)
- 格式: 6位数字
- 前缀: `sms:code:{phone}:{type}`

### 8.3 文件上传

- 支持格式: PDF, Word (.doc, .docx)
- 文件大小限制: 10MB
- 存储: 阿里云OSS (需配置)

### 8.4 AI简历解析

- 异步处理模式
- 解析状态: 0未解析, 1解析中, 2已解析
- 结果存储: JSON格式

## 10. 联调准备

### 10.1 前端对接说明

#### 认证流程

1. 前端调用 `/api/v1/user/send-code` 发送验证码
2. 前端调用 `/api/v1/user/login-phone` 登录，获取 `accessToken` 和 `refreshToken`
3. 前端将 `accessToken` 存储在本地
4. 前端请求时在 Header 中添加 `Authorization: Bearer {accessToken}`
5. 当 `accessToken` 过期时，调用 `/api/v1/user/refresh-token` 刷新

#### 简历流程

1. 调用 `POST /api/v1/resumes` 创建简历
2. 调用 `POST /api/v1/resumes/upload` 上传简历文件
3. 调用 `POST /api/v1/resumes/{id}/parse` 启动AI解析
4. 调用 `GET /api/v1/resumes/{id}` 查询解析状态和结果

### 10.2 错误处理

| 错误码 | 说明 | 处理方式 |
|--------|------|----------|
| 1001 | 参数错误 | 检查请求参数 |
| 2001 | Token无效 | 重新登录 |
| 2002 | Token过期 | 刷新Token |
| 3001 | 资源不存在 | 检查ID是否正确 |
| 3003 | 业务状态错误 | 检查操作顺序 |
